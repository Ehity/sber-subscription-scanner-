# Правила анализа выписки (спецификация)

Доменные правила, по которым `backend/analyzer.py` (и его JS-порт
`frontend/src/lib/analyzer.js`) превращает выписку в список подписок.

## 1. Источники данных

- **CSV**: кодировки `utf-8-sig` → `utf-8` → `cp1251`; разделители `;`, `,`, таб
  (csv.Sniffer); заголовки распознаются по словарю алиасов `COLUMN_ALIASES`
  (рус/англ), при неузнаваемых заголовках — эвристика по содержимому ячеек.
- **PDF**: только текстовые выписки Сбербанк Онлайн (не скан), три формата строк:
  многострочный (дата / сумма / описание отдельными строками), однострочный,
  «дата + код авторизации + описание».

## 2. Нормализация названий

- Справочник брендов `BRAND_RULES` (~29 сервисов): имя, категория, эмодзи,
  ключевые слова. Ключи узкие, чтобы не ловить «Яндекс Такси» вместо
  «Яндекс Плюс».
- Аббревиатуры `ABBREV_MAP`: NFLX→NETFLIX, SPOT→SPOTIFY, YNDX→YANDEX.
- Мусорные токены `STOP_WORDS` (страны, домены, формы собственности).
- Описание чистится от URL, цифр, телефонов, хвоста «Операция по карте ****».

## 3. Фильтры (не подписки, даже если регулярные)

- `INTERNAL_RE` — переводы самому себе, банкоматы, депозиты.
- `UTILITY_RE` — ЖКХ, налоги, ГИБДД, платежи по СБП (включая транслит
  `uslu`, `uchrezd`).

## 4. Правила детекции

1. Отбрасываются списания меньше 1 ₽ (артефакты верификации карты).
2. Транзакции группируются по брендовому ключу либо по нормализованному имени.
3. Группы склеиваются по близости имён: Dice ≥ 0.8 (группа→группа),
   Dice ≥ 0.75 (группа→бренд).
4. Минимум списаний: 2 — для известного бренда, 3 — для остальных.
5. Цены кластеризуются с допуском ±15%; цена подписки = медиана актуального
   (последнего) кластера. Так переживает промо-цену (99 ₽ → 299 ₽).
6. Дубликаты одного дня (интервал < 10 дней) не считаются отдельными списаниями.
7. Периодичность по медианному интервалу: 20–40 дней → «ежемесячно»,
   340–390 дней → «ежегодно», иначе группа отбрасывается.

## 5. Смена цены

`detect_price_change`: цена подтверждается на уровне ±5% (≥2 платежа на
уровень). Одно повышение тарифа фиксируется как `price_change`
(oldPrice, newPrice, percentChange, direction).

## 6. Выход детекции

Для каждой подписки: id, name, category, icon, monthly_cost, yearly_cost,
charges (даты списаний), next_charge, merchants, price_change. Сортировка —
по monthly_cost по убыванию. Экономия считается только по положительным
стоимостям.
